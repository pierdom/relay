### How the merges actually went

Each branch took `main` in before merging, with CI green on the merged head and a fresh `docker build` + live smoke that re-checked the *earlier* PRs' fixes through the new code. Two resolutions were more than mechanical:

- **`relay/service.py` in #113** (deleted here, modified there). Rather than hand-porting main's hunks into the package — one dropped hunk is a reverted security fix — the package modules were **regenerated from main's merged `service.py`**, then #113's own edits re-applied on top. Presence of every fix was then checked by name (`InvalidFolder`, `InvalidTag`, the page clamps, `tag_folder_filters`, `degraded`, the `len(sha) < 4` guard, `is_valid_name`, the empty-filter normalisation) alongside #113's (`folder_of` ×5, the `update_post` narrowing, `add_attachment`'s `row["id"]`). `MAX_PAGE_LIMIT`/`MAX_HISTORY_LIMIT`/`_clamp` moved to `_common`, shared by `posts` and `revisions`.
- **`relay/routes/auth.py` — a silent revert git could not flag.** #113 moved `POST /session` out of `main.py`; #111 had changed the *original* to `bearer_matches`. The moved copy still held `hmac.compare_digest`, so a clean merge would have quietly undone S-04 on that route. Caught by auditing which code #113 had relocated and diffing what #111/#112 changed in the source files; the middleware moved to `metrics.py` was checked the same way and was untouched. Re-applied in the merge commit and re-verified live (`/session` bad key 401, good key 200).

The rest: keep the bridge in `relay_mcp/server.py` (both #112's and #114's edits to the old manifest are moot — descriptions and tools come from the server), `folder_of` + `is_valid_name` in `folders.py`, `_clean_title` + `normalize_expires_at` in `models.py`, G-03 ported into `service/tags.py`, README/`docs/stability.md` at 22 tools, all changelog sections retained.

Things learned during execution, in the register's terms:

- **The browser smokes pass vacuously on `main` in an offline sandbox** (jsdelivr unreachable → `marked` never loads → no Markdown renders → the theme walker sees no tables). Vendoring the libraries (S-03) made the UI render offline and exposed Chromium's UA-default `table { border-color: gray }`, the one colour outside every palette. Fixed in #111 with `border-color: var(--border)` on `.post-body table`. Full `tests/ui` result on #111 is posted on the PR.
- **`Last-Event-ID: 0` performs no replay** (`if last_event_id and high_water`). Not reachable from a real client — `id: 0` is never emitted — so left alone; noted here rather than filed.
- **The slim image has no `/etc/mime.types`**, so `mimetypes` in the container resolves `.xht` to `application/octet-stream`, not `application/xhtml+xml` as on a dev host. That is why S-01's inline allowlist also sends unknown types as downloads — "unknown here" can be "active there".
- **Docker verification in this sandbox** needs a verify-only Dockerfile variant (apt over https + the egress proxy's CA mounted as a build secret); the committed Dockerfile differs from it only by the digest pins and `USER`. Stated in every PR body.

## 1. System map

### Layers

```
transports          relay/routes/*  (REST)     relay/mcp_server.py (MCP, in-process)     relay/routes/events.py (SSE)
                    relay/main.py   (/, /ui, /static, /session, /health, mounts)
                             │                          │
service              relay/service.py  ─────────────────┘      relay/status.py (diagnostics + embedding control)
                             │
persistence          relay/vault.py (files = truth, id counter, index mirror, backfill)
                     relay/database.py (SQLite index + FTS5)   relay/vectors.py (sqlite-vec, cache, KNN, RRF)
                     relay/history.py (git-dir under .relay)   relay/ingest.py (URL fetch, upload slots)
side channels        relay/watcher.py (watchdog → reindex + SSE)   relay/cleanup.py (TTL sweep)   relay/events.py (fan-out)
pure helpers         frontmatter.py · folders.py · links.py · chunking.py · embedding.py · metrics.py · models.py · auth.py · config.py
auth add-ons         relay/routes/auth.py (OIDC web login)   relay/mcp_oauth/* (OAuth 2.1 AS for /mcp)
clients              relay_mcp/server.py (stdio proxy → REST)   relay_tui/* (Textual → REST + SSE)   relay/static/ui (browser SPA → REST + SSE)
```

### Who calls what

- **REST routes** are thin: parse → `service.*` → map exceptions to HTTP codes. Good.
- **In-process MCP** (`mcp_server.py`) calls the same `service.*`/`status.*` functions. It opens its own connection via a private `_db()` that duplicates `database.get_db`.
- **stdio proxy** (`relay_mcp/server.py`, 923 lines) does *not* share the service layer: it hand-copies all 21 tool schemas and re-implements every tool as an HTTP call plus bespoke text formatting. `tests/test_mcp_parity.py` exists only to police that duplication.
- **TUI** talks REST (`requests`) + SSE. It re-declares the wikilink/id-ref regexes from `relay/links.py` in `relay_tui/widgets/modals.py`.
- **Browser UI** talks REST + SSE; renders Markdown with `marked` + `DOMPurify` loaded from jsdelivr.
- **Writes** go file-first (`vault.write_file`) then index (`vault.index_*`), under `vault.write_lock` (a coroutine lock; the process is single-worker by design). `history.commit` runs *after* the lock is released, serialised by its own lock.
- **Watcher** and **cleanup** open their own connections and write to the index; cleanup does not take `vault.write_lock`.
- **Embedding sync** is called inline from `index_insert`/`index_upsert` (write path) and from the background backfill.
